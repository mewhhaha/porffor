# T23 — Complete ECMA-402 Intl implementation

**Status:** In progress — `Intl.getCanonicalLocales` now combines its observable per-index array-like walk with one pinned locale provider/import and pre-instantiation artifact identity gate; complete locale/Intl services and artifact data images remain open

**Parallel group:** Feature lane; split by Intl service after shared locale/options foundations  
**Depends on:** T06, T10, T18, T20, T22  
**Blocks:** `intl402` and locale-sensitive T26 closure

## Current repository state

The product Wasm backend has structural locale canonicalization,
`Intl.getCanonicalLocales`, a partial `Intl.Locale`, and a substantial
DateTimeFormat slice. DateTimeFormat currently has one locale (`en-US`),
Gregorian/ISO calendars, `latn`, fixed-offset zones, and handwritten patterns;
it is not the general data-backed service required by ECMA-402. No other Intl
service family is complete. The extensive Intl service code under vendored
Boa/spec-exec is oracle-side and does not count as Wasm-AOT support. The
`intl402` suite is not current-pin green, so this remains one of the largest
open feature lanes.

`lila-intl` owns the shared runtime seam. Its data
identity requires a typed canonical default locale and fixes schema, profile,
placement, digest and upstream versions together. A sealed `IntlHostOp`
catalogue associates locale and time-zone canonicalization with distinct
request/result/error types and required data capabilities. `IntlKernel` accepts
only an identity-matched provider, then grants an operation-specific handle
only when the selected profile proves the operation's capability. Raw strings,
cross-operation requests, profile plans without artifact identity, and
provider/artifact identity mismatches therefore cannot silently enter the
kernel.

The first real product call now crosses that seam. `lila-intl` directly pins
`icu_locale = 2.0.0` and `icu_locale_data = 2.0.0`; a host-embedded,
Locale-only provider exposes the data archive digest and `External` placement
relative to emitted Wasm. `Intl.getCanonicalLocales` performs all observable
element work and structural validation in Wasm. It keeps the original
array-like object, snapshots `length` once, and then performs HasProperty,
conditional Get, coercion, provider canonicalization and deduplication before
advancing each index. Holes are skipped, inherited indices and primitive
wrapper prototypes participate, Proxy `has` abrupt completions propagate, and
an earlier element's coercion can change a later element. Primitive boxing,
null rejection and the result Array prototype use the called builtin's defining
Realm. Only then does the typed `CanonicalizeLocale` operation resolve CLDR
aliases, so `iw-IL` and `he-IL` converge. The shared ABI has typed read/write
spans, stable operation wires, and a closed written/rejected result domain; the
engine rejects unknown operations, malformed memory/UTF-8, output overflow,
provider-data faults, and the deliberately unbound time-zone operation.

The shared Proxy internal-method implementation still creates some of its own
errors in the main Realm. This slice guarantees unchanged propagation of a
user-thrown Proxy `has` sentinel, not correct defining-Realm provenance for
Proxy-generated TypeErrors; that remains owned by the shared object seam.

The defining-Realm ToObject and result-Array paths are source-structural and
independently reviewed, not runtime-proven across realms. Created realms do not
yet install `Intl`, so a foreign `Intl.getCanonicalLocales` witness is
unreachable. T06/T23 created-realm Intl bootstrap must land before runtime tests
can prove foreign Number wrapper lookup, foreign null TypeError identity and
foreign `%Array.prototype%` result identity.

Every emitted module that imports `lila_host.intl_call` now carries exactly one
`lila.intl-data-identity.v1` custom section. `lila-intl` alone serializes the
complete identity canonically; the emitter cannot construct a partial metadata
record, and the engine compares those canonical bytes to the shared
`EmbeddedLocaleProvider` identity before Wasmtime compilation or
instantiation. Missing, duplicate, mismatched, and import-less unexpected
sections are typed engine errors. Since the identity lives in the Wasm bytes,
program and module caches preserve the gate without parallel cache metadata.

This remains a narrow slice. `Intl.Locale` is intentionally not routed through
the provider because its component slots still come from the structural pass;
doing only the tag would make the object internally inconsistent. There is no
generated artifact data image, artifact-embedded ICU payload, general locale
matching, or time-zone/provider integration yet. The carried identity describes
the external host provider and enforces its digest; it is not the future
`Embedded` data image. The central feature-enabled CLI compile is green, as are
focused contracts for canonical artifact encoding, typed host-import selection,
pre-instantiation identity rejection and locale-alias resolution before
deduplication. No full-tree green count is claimed here.

The time-zone operation is not merely waiting for a linker arm. The resolved
`timezone_provider 0.1.2` canonicalizer identifies its baked alias data as
tzdb `2025b`, while the shared transition line promised by T22/T23 is `2026a`.
Binding those together would advertise an identity the inputs do not have, so
the operation stays explicitly unavailable until one coherent catalogue owns
both canonical names and transitions.

## Objective

Implement the pinned ECMA-402 revision in the Rust/Wasm product path with reproducibly pinned locale, Unicode and time-zone data. Do not count delegation to Boa's spec-exec engine as AOT Intl support and do not depend on the embedding process locale for observable results.

## Architecture and data strategy

[`docs/rust-rewrite/intl-architecture.md`](../docs/rust-rewrite/intl-architecture.md)
is the source of truth. It selects:

- an exactly pinned ICU4X 2.0 line with CLDR 47.0.0, Unicode 16.0.0, ICU data
  tag `icu4x/2025-05-01/77.x`, segmenter data v0.1.0, and shared IANA tzdb
  2026a as the first complete conformance data line;
- a versioned immutable data image with `Conformance`, `Minimal`, and validated
  custom profiles, embedded by default or supplied through an explicit
  digest-matched embedder capability;
- one time-zone identifier/transition catalogue shared with T22, with localized
  zone names layered on top rather than a second transition source;
- an emitted-Wasm observable shell followed by a typed Rust Intl kernel that
  accepts only fully observed, canonicalized primitive records; and
- closed service, host-operation, profile, placement, and data-capability
  domains so incomplete profiles and cross-service handles are rejected by
  construction.

The existing `lila_host` mechanism is the initial pure-kernel transport, but it
may not call host-native Intl or inspect JavaScript objects. Artifact/provider
schema or digest mismatch is rejected before Wasmtime instantiation through the
artifact-carried identity. The default locale and all formatting data come from
the selected artifact profile, never the process or operating system.

The default conformance build must include every locale/data item needed by the pinned Test262 suite. Missing data must produce specification-compliant fallback, not an internal error or English-only shortcut.

## Implementation order and parallel seams

1. Complete the shared `lila-intl` foundation. The typed data identity, exact
   locale pins, host-embedded locale kernel and first consumed Wasm ABI
   operation have landed. Canonical artifact identity metadata and
   pre-instantiation provider matching have also landed. Deterministic artifact
   image generation/validation and the remaining operation bindings remain.
2. Finish shared locale/options operations and replace the bootstrap locale
   tables. This owns canonicalization, matching, extensions, Locale and
   `supportedValuesOf`.
3. Implement services concurrently behind service-specific validated request
   and result types: NumberFormat/PluralRules, DateTimeFormat/T22 integration,
   Collator/Segmenter, and ListFormat/DisplayNames/RelativeTime/DurationFormat.
4. Integrate locale-sensitive core builtins, remove the bootstrap-only tables,
   measure conformance/minimal profiles separately, and run the full closure
   gates.

Service files are parallel-owned. The locale/options layer, data manifest,
host-operation catalogue, intrinsic registry and artifact ABI are
integrator-owned shared files.

## Shared Intl abstract operations

Implement one common layer for:

- structurally valid language tags and Unicode locale identifiers;
- canonicalization, grandfathered/deprecated aliases and extension handling;
- `CanonicalizeLocaleList` with array-like length, HasProperty, getter and
  coercion ordering;
- locale lookup/best-fit matching and supported-locales results;
- options object conversion and `GetOption`/`GetNumberOption` behavior;
- Unicode extension key negotiation;
- numbering systems, calendars, collations, hour cycles and time zones;
- `resolvedOptions` object creation and ordered properties;
- shared constructor call/new-target and legacy-constructor behavior where specified.

All JavaScript-visible reads/calls must use T04/T10. ICU inputs may be prepared only after observable access and validation are complete.

## Service families

Implement every constructor/prototype/API present in the pinned suite, including as applicable:

- `Intl.Collator`;
- `Intl.NumberFormat`, range formatting and format-parts APIs;
- `Intl.DateTimeFormat`, range formatting, format-to-parts, calendars and time zones;
- `Intl.PluralRules` and range selection;
- `Intl.RelativeTimeFormat`;
- `Intl.ListFormat`;
- `Intl.DisplayNames`;
- `Intl.Segmenter` and segment iterator/containing behavior;
- `Intl.Locale`, maximize/minimize and locale-info accessors;
- `Intl.DurationFormat`;
- `Intl.supportedValuesOf`;
- locale-sensitive String, Number, BigInt, Date and Temporal methods.

Track the pinned ECMA-402 revision rather than assuming the list above is complete.

## Object and realm semantics

- Install exact constructors, prototypes, accessors, method names/lengths and descriptors from the intrinsic registry.
- Enforce internal-slot branding for extracted methods and cross-realm receivers.
- Implement bound formatter getter identity/caching rules.
- Preserve subclass/custom-new-target behavior where constructors permit it.
- Keep resolved option values and property ordering exact.

## Formatting correctness

- Use pinned CLDR/Unicode data and expose expected canonical aliases.
- Handle NaN, infinities, signed zero, BigInt and extreme Date/Temporal values.
- Preserve required rounding modes, increments, notation, sign display, grouping and currency/unit rules.
- Ensure parts arrays and range source annotations have exact structures/descriptors.
- Segmenter indices are UTF-16 code-unit indexes, not UTF-8 byte offsets.

## Performance and artifact size

Add benchmarks for constructor setup, cached formatting, segmentation and artifact/data size. Caching is allowed only when user-observable option/property reads have completed and realm/object identity rules are preserved. Report the conformance build's data footprint separately from a minimal production profile.

## Acceptance criteria

- The complete pinned `intl402` tree is green under Wasm-AOT.
- All locale-sensitive methods in core builtins pass their adjacent Test262 filters.
- Results are reproducible across supported hosts with the same pinned data.
- Locale/options access-order tests pass with proxies, accessors and thrown values.
- No service silently falls back to host locale formatting or an English-only handcrafted formatter.
- Constructors, bound functions, branding, descriptors and cross-realm tests pass.
- Data version and build profile are visible in diagnostic/artifact metadata.
