# Mixed Switch analysis ownership

An async-generator Switch preserves the FunctionBody domain only when the actual
checked mixed Switch source factory accepts that AST. Foreign iterator and
resource ancestry stays sticky even when the same Switch shape would be lawful
at function scope. A refused body keeps its original foreign routing. Ordinary
generator and plain Async analysis domains retain their own protocol authority.

Nested With statements continue to consume their existing opaque AST-identity
token. Their original hidden object rows are reserved before physical slots and
capture hops are assigned. The CaseBlock and a nested source Block remain distinct
original lexical records. No new capture or environment representation is added.

The shared private CheckedSwitchStorageIr admits the actual invocation cells,
their distinct names and slots, the sole terminal discriminant publication and
the original uninitialized CaseBlock record. Both protocol carriers store that
proof. Public constructors and getters remain unchanged; selector order, default
selection, complete body ranges and suspension tape are checked by each actual
protocol carrier. A child record may reuse an invocation slot number, since
those slots name different records. Old constructor controls damage actual raw
arguments before admission instead of mutating the private proof.

Analysis controls inspect real CaseBlock, nested Block and With captures;
structurally lawful switches under foreign iterator/resource ancestry; and
independent nested callable domains. Existing mixed With control names and source
literals are retained, with the newly checked eager Switch row now admitted.
All controls are authored source only and await the complete batch verification.
