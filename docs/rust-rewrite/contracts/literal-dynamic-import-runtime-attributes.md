# Literal dynamic imports with runtime attributes

A literal specifier and statically known attributes are independent facts.
`import('./data.json', options)` retains a literal locator even when evaluating
`options`, its `with` property or its enumerable attribute properties is needed
to learn the exact host request. Projecting that discovery to an empty attribute
key cannot substitute for declaring the supported attributed records.

`ModuleSourceIr::dynamic_import_sites` projects the retained Script or Module
AST without another grammar parse. Its closed Known/Runtime attribute metadata
and optional literal specifier are consumed independently by the Test262 host
catalog. `DynamicImportSiteIr::permits_catalog_key` shares admission's exact
known-attribute and scalar-string eligibility rules. Display spellings of lone
surrogates cannot mint different host identities. Synthetic Text/JSON/Bytes
records contain no import sites and rejected grammars expose no site list.

For a literal site with Runtime attributes, the catalog attempts only the
supported JSON, Bytes and Text variants of that exact specifier, under existing
root confinement, extension and strict UTF-8 policies. It does not enumerate
unrelated fixtures. Computed-specifier expansion is driven by the actual AST
site metadata and filters those rows against its exact Known/Runtime
attribute metadata; comments or strings that resemble import calls cannot
trigger it. A cheap existing source prefilter still avoids building Script catalogs for
ordinary code; it does not choose request rows or attribute values.

The emitted import still evaluates options and live Proxy ownKeys, property
descriptors and enumerable values in their specification order. Non-enumerable
and Symbol keys are not converted into attributes. Unknown/extra attributes,
non-String values and abrupt hooks keep their original rejection behavior.
Declaring finite candidates never chooses or evaluates one before the runtime
request matches its complete exact key.

IR controls distinguish literal Runtime attributes, computed known unsupported
attributes, comments, rejected source and unrepresentable host keys. Catalog
controls prove exact-locator expansion and unsupported-key exclusion. A native
Test262-host control exercises sloppy and strict Script goals, options
identifiers, live Proxy enumeration, JSON/Text/Bytes selection, non-enumerable
attributes, extra/non-String attributes and abrupt options identity. Historical
enumerable-attribute execution IDs and every prior passing ID require native
replay before acceptance.
