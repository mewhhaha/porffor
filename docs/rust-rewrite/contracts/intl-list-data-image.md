# List data image and admitted formatter ownership

This source batch supplies a real immutable ListFormat component image. The
complete twelve-component successor now uses Embedded placement for the finite
pinned data closure. A Locale/List payload alone does not establish that closure
or a full Conformance profile. MAIN142 type-checked this foundation; native
controls, emitted artifacts and pinned acceptance remain pending.

## Complete data and actual consumers

`src/image_build/list.rs` exports all exact data identifiers of the pinned ICU
`ListAndV1`, `ListOrV1` and `ListUnitV1` markers. It loads every declared row,
rejects a load unexpectedly resolved through fallback, and flushes all three
markers into one BlobExporter. Ordered identifiers and the exporter's sorted
resources produce deterministic bytes without a native hash iteration order.
Build-time inputs remain exact locked ICU data; no OS locale or filesystem data
lookup enters runtime formatting.

The shared image envelope binds component, schema, upstream versions, profile,
marker names and actual content digest. Admission also requires the blob bytes
to equal this compiler's generated locked component, rather than accepting an
arbitrary payload carrying the pinned version labels. Existing named Custom IDs continue to label that same exact pinned data. The
`CustomProjection(CustomIntlProfile)` compilation selection supplies a real List
projection inside the complete twelve-image bundle. Its optional RelativeTime
filter can independently select actual native rows under the same Custom ID;
absent component filters retain their full payloads. The other ten payloads remain
full. General twelve-component filtering and Conformance generation
remain open work.
Minimal/custom component frames are distinct from the deliberately unavailable
complete Conformance image. A frame
or advertised marker list alone cannot construct `ListDataImage`: the raw blob
must decode, all three actual inventories must be nonempty, and the existing
ListProfiles owner must load all nine conjunction/disjunction/unit and
long/short/narrow constructors for every canonical available locale and the
en-US default. Only that completed owner publishes resolved locale proofs.

The consumer uses `BlobDataProvider` through typed deserialization and
`LocaleFallbackProvider`. Canonicalization and fallback data come from the same
validated selected Locale component, including its consumed LocaleParentsV1
marker. Runtime has no baked List provider or baked fallback. For complete images, AvailableLocales still derives from actual loaded
identifiers; an unrelated NumberFormat list or pooled pattern count cannot claim
List support. A projected image publishes its checked explicit locale set plus
en-US, independently of its physical fallback and private dependency rows.
Each formatter admission
captures the effective locale returned by its actual load, preserving such
associations as en-US to en.

ICU 2 serializes conditional List DFAs as little-endian bytes. Its big-endian
binary decoder silently omits those conditions; this adapter explicitly rejects
that host representation before publishing List profiles. It therefore cannot
silently replace contextual Spanish/Hebrew joins with unconditional templates.
The blob byte form remains deterministic across generation hosts. Current
supported little-endian Linux/macOS hosts retain the same actual templates.

## Actual List projection producer and reader

`ListDataImage::for_custom_projection` consumes `CustomListProfile` from the real
SDK compilation selection. Its structurally checked requested locales are
canonicalized by the selected complete Locale canonicalization, reserved-language
and keyword authority, then checked against the full pinned List catalogue.
Duplicate canonical names and names absent from that catalogue reject. The
public set always contains the genuinely admitted en-US default. Minimal and
existing full `Custom(id)` component bytes keep their original exact framing.
The native `CustomListProfile` remains the checked List input, obtained from
`CustomIntlProfile::list_projection`; combining a RelativeTime filter does not
alter List row, public catalogue or private Duration admission.

The private projector runs the same nine formatter constructors as normal image
admission. A recording provider sits inside the genuine LocaleFallbackProvider,
so it records successful physical DataIdentifiers rather than guessing parent
rows from text. Every identifier retains its marker, locale and actual width
attribute: ICU requests N, S or W for each of list/and/v1, list/or/v1 and
list/unit/v1. The private exporter loads those exact rows from the immutable full
pinned Blob and uses ICU's typed BlobExporter. Binary serialization retains the
conditional DFA bytes in little-endian form; there is no baked runtime fallback
or OS data lookup.

The Custom-only `LILALIP1` payload contains a canonical descriptor and the actual
subset Blob. The descriptor binds schema, Custom ID, en-US default, full List
Blob SHA256, selected Locale image digest, unchanged native Duration source pin,
public locale set, exact fifteen Duration associations and sorted physical rows.
Its extent is checked before decoding; descriptors are capped at 512 KiB and
whole component images retain the common 64 MiB bound.

Readers recompute this precise derivation from the pinned full data and selected
Locale image and require complete byte equality. This verifies actual row
provenance, complete widths, canonical export layout and absence of extra data,
beyond the shared envelope's digest. Only then do all nine constructors load
from the actual subset Blob to publish profiles. The raw complete payload path
still requires exact full pinned bytes. Arbitrary version labels or an invented
source digest cannot admit another payload.

The fifteen native Duration associations are derived through the same public
prefix-matching authority over the full pinned catalogue. The projected owner
retains those required profiles privately, using the same profile Arcs and data
as its public profiles. Duration consumes a restricted association lookup for
its unchanged fifteen source rows; it keeps its exact native payload, selected
Number owner and selected List owner. Its final composition continues through
that selected List owner's format_parts operation.

Public available_locales, resolve, supported and admit use only the checked
public set. Both resolved List wire decoders consume admit, so private Duration
profiles cannot be reminted through an external List request. Native Duration
may format its genuine retained private configuration, and format_parts still
checks the exact profile Arc against this selected owner before using data.
Thus an es/he projection can preserve Duration's ar/sr output without claiming
public ar/sr ListFormat support.

## Retained configuration and selected data

`ListDataImage` owns its immutable frame, the selected Locale image digest and
`Arc<ListProfiles>`. The provider admits the pair only when that retained
foundation digest equals its selected Locale image, before formatting requests
can run. The profiles' actual formatter payloads retain the blob data.
`ResolvedListLocale` retains its
exact profile Arc, and CheckedListConfiguration keeps that owner together with
closed type/style choices. No independent profile number or locale string can
replace it. Dropping another image handle does not invalidate a live request.

The selected provider invokes `ListProfiles::format_parts`, which locates the
retained locale in its own catalogue and requires the exact retained profile
owner. A request resolved under a different image instance cannot flow through
another provider merely because the locale text agrees. Direct pure native
formatting may still consume its own complete retained configuration; the
selected kernel enforces its image ownership at the operation boundary.

The existing all-locale/nine-configuration control now compares real image-backed
formatters with the independent pinned ICU constructors. Existing contextual,
UTF16, partition and effective-fallback controls remain unchanged. One new
control admits two actual image owners and rejects transfer of a resolved
configuration while its original owner still formats it successfully. These
sources are executable obligations, not current pass results.

Four additional native controls cover a physically smaller Blob and all nine
selected formatter choices, contextual Spanish/Hebrew conditions and lossless
UTF16; private Duration associations and both wire refusal paths; all fifteen
Duration rows/four styles with the exact selected List Arc and retained lifetime;
real width-row omission and forged source pins despite valid framing; and
canonical reproducibility while complete Minimal/full Custom payloads stay
byte-exact. The shared Engine/CLI lane consumes the same selection through
ordinary compilation, cache identity, build and run. These new source controls
have not yet been compiled or executed.
