# Generated builtin scenarios and metamorphic replay

T25's `builtin-stateful-v2` and `metamorphic-stateful-v2` produce dependency-sealed Script source for the existing selected workers. Wasm AOT executes the compiled user program; the separately selected spec oracle observes that same source. The producer never computes an expected semantic trace, interprets its action plan, supplies an engine fallback or treats matched backend failures as success. The v1 grammar names retain their original six-family seed mapping, strictness, transformation selection and exact rendered requests for previously retained pair replay.

`ScenarioGenerationPlan` fixes the grammar, seed and nonzero action budget. It reuses the existing control-flow step limit, worker timeout, request/output limits and serial low-resource campaign. Private checked action plans bind every operation to its actual family, numeric operand and bounded slot. V2 seeds select eight families: Array mutation and shared ArrayBuffer/TypedArray/DataView views; synchronous iterator close; Map/Set mutation and visitation; Proxy traps and primitive coercion hooks; Array/TypedArray subclasses and species; Promise reaction, thenable, rejection, finalizer and async job sequences; cross-Realm builtin calls; and Temporal value sequences. Promise terminal handlers emit progress only after the actual jobs complete; rejection emits a failure marker without a terminal success marker.

The fixed setup and checkpoint harness adds transitions outside the generated action budget. The action switch is finite and executes each selected action once. Array growth is bounded by the action count; the buffer has eight bytes. Map/Set keys remain in `0..=15`, and visitation inserts each `key+8` only for keys below eight, so callbacks cannot create unbounded chains. Each custom iterator has at most three values. Promise actions attach a finite number of reactions to an owned finite chain. There are no network requests, clocks, randomness in emitted source, dynamic evaluation or unbounded job producers. Only the cross-Realm family requests a conformance host capability.

The cross-Realm setup calls the existing native `__lilaCreateRealm` once. Its eight actions exercise borrowed Array map, observable species selection, primitive boxing, the called builtin's TypeError Realm, Map brand checks and shared state, TypedArray species, Reflect construction with an explicit prototype, and exact identity of a marker thrown by an accessor. The actual objects stay in JavaScript; observations contain primitive prototype/marker comparisons, values and ordered hooks. Actions neither mutate Realm intrinsics nor depend on a preceding action to initialize a binding.

That family explicitly selects native schema v6, `V6Test262HostPrimitivePrintTranscript`. Its wire and fingerprint grant the existing full `HostSurfacePolicy::Test262`, including real Realm creation; this is not a new Realm-only host policy. Schemas v1–v5 remain Product regardless of source, filename or case id. V6 retains reject-all module loading, the existing worker executable/oracle gates and limits, and v3's primitive completion/ordered-print contract. The protocol is bound into the worker request, fingerprint and report; it is not inferred from a source substring or a journal label. Product Temporal cases retain v3. A pair that changes either variant's protocol fails exact producer admission.

The Temporal family starts with an ISO date, an exact BigInt Instant and a fixed-offset ZonedDateTime. Its eight actions add or replace date fields with observable overflow options; add exact nanoseconds; change a fixed offset and add days; round, total and compare finite Durations with retained relative values; observe ZonedDateTime property/option conversion order; and check exact abrupt-marker identity through PlainDate conversion. Numeric operands remain in `-16..=16`, slots in `0..8`, valid rounding increments come from a closed list, and date-field mappings remain valid when an operand shrinks to zero. It uses no `Temporal.Now`, system clock, named time-zone or locale data. The observer receives actual fields, exact epoch decimal strings, numeric results and hooks, not arbitrary Temporal object snapshots.

Metamorphic replay runs the original and transformed source independently on both backends. The renderer lawfully changes one private, unreflected accumulator binding, encloses an action in a neutral lexical block, or replaces the fixed finite `for` driver with a `while` whose update follows the same switch. This switch has no driver-targeting `continue`; its `break` exits only the switch. Property keys, printed labels, callback ordering and generated actions stay the same. No textual search-and-replace can accidentally rename a property or a string. Both exact sources and both original backend reports are retained by the shared campaign journal. Observation fields are private and exposed through read-only getters; callers cannot replace a report, source or relation while retaining a green verdict.

The final reduced pair is separately retained at `evidence/case-NNN.pair.json`, alongside the original request/report journal. `ScenarioReplayPair` uses a strict versioned native wire: grammar/seed/budget, closed typed actions, selected transformation, expected actual action count and both exact requests with their native authority. Admission validates the program and count, then regenerates both variants with the sole source producer and requires exact request equality. Unknown fields, foreign source, unsupported protocols and forged checkpoints are rejected before worker selection. This pair format is not an ordinary corpus entry. Individual corpus inputs remain useful for per-source differential replay; only paired replay reproduces the within-backend metamorphic relation.

```sh
lila differential replay-scenario-pair evidence/case-000.pair.json --oracle spec-exec
```

That command runs both actual variants using the selected bounded workers and prints both untouched backend reports plus the observed relation. A failed baseline worker stops before launching the transformed pair; the record retains the exact pending transformed input and marks the relation unavailable. The pair artifact remains available for later replay, and the campaign stops subsequent cases. No synthetic transformed observation is created.

A successful record requires actual normal primitive completions, all ordered action checkpoints and the final completion marker, plus both differential matches. Metamorphic success additionally requires each backend's original/transformed primitive completion and ordered print transcript to match under the same worker identity. This establishes only the declared primitive/print relation, never full program equivalence. Engine errors, both-failed frontends, timeouts, incomplete output, unsupported completion values, missing progress and unavailable cross-source observations remain red.

Reduction removes actual actions or shrinks bounded operands, replaying both variants when a relation is requested. It preserves scenario family, strictness and transformation, each source's differing completion/print dimensions and completion kinds, one-backend failure phase and the other backend's completion kind, and the two within-backend metamorphic difference dimensions. Source-dependent fingerprints are replaced only by actual candidate reports. Cancellation between either pair of replays propagates without publishing an earlier candidate; the journal keeps the already observed attempt. A failed worker cannot become a reduced green record.

Arbitrary cross-Realm object graphs, weak-reference collection timing, external I/O, host buffer detachment, clocks, non-ISO calendar generation and a general Temporal object observer remain explicit coverage gaps. Private controls exercise source admission, parser syntax, all actions/transformations, red progress guards, replay identity, cancellation and reducer fidelity. The v2 controls reject changed host authority or reinterpretation of v1 pairs and preserve service witnesses through exact reduced-pair replay. The selected-worker control `realm_and_temporal_campaigns_retain_all_eight_actions_and_actual_paired_observations` uses seeds 1270 and 3215, each selecting all eight operations once, with original/transformed actual reports. Existing controls cover the original six families, all three relations and one-command paired CLI replay. The serial PR tier selects v2 seeds 6 and 7 so it actually reaches both new families. These new controls are authored; compilation and execution remain pending the joined checkpoint.
