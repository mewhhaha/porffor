# AsyncDisposableStack GC lifecycle

The authored native implementation stores the stack header, lifecycle, and private resource List in `AsyncDisposableStackObject`. The List owns a typed resource table and count; each resource retains whole `StoredValue` resource and method records. Registration captures the List before observable method lookup, so a getter that calls `move()` appends to the List transferred to the new stack. A getter that begins disposal cannot change the already-started walk's captured table or entry limit. Consumed nullable entries remain nullable when a reentrant registration grows the old List.

The constructor uses the shared completed GetPrototypeFromConstructor owner with the closed AsyncDisposableStack selector. Methods require the actual GC record; inherited properties, user-created slot names, and a Proxy around a stack cannot supply its private slots. Move publishes a new stack in the called method's Realm, transfers its List, then leaves the original disposed with a fresh List. All source Get and Call failures retain whole completions and their original values.

Use observes optional `@@asyncDispose` once, then optional `@@dispose` only after nullish absence. Callable Proxies are valid. The synchronous fallback captures its original method in a closed builtin capture, creates an intrinsic acquisition-Realm Promise capability before Call, and resolves undefined without observing the method's returned Promise or thenable. Adopt and Defer use their specified original receiver and argument Lists.

DisposeAsync creates its intrinsic Promise before receiver validation and rejects that Promise on brand failure. It marks the stack disposed before any callback. A private captured disposal record owns the outer Promise, disposal Realm, table, reverse index, closed Normal/Throw completion kind, whole error value, and the `needsAwait`/`hasAwaited` Boolean states. Fulfillment and rejection callbacks resume that same record. Synchronous Call failure folds an error and continues immediately. A normal Call begins Await; synchronous PromiseResolve failure folds the exact Throw and resumes immediately, while successful setup parks the walk until its callback. Rejected Await also folds the original reason. Multiple errors allocate SuppressedError using the retained disposal Realm and preserve the newest error and previous suppression as whole values.

Null or undefined Use entries set `needsAwait` without individually suspending. The walk performs one final Await(undefined) only when such an entry exists and no method Await has occurred. An Await setup failure still counts as an attempted Await, as does a rejected Await. Empty stacks and already-disposed stacks complete without that extra suspension. This follows [DisposeResources](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-disposeresources), [GetDisposeMethod](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-getdisposemethod), and the [AsyncDisposableStack methods](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-asyncdisposablestack-prototype-object).

The existing six Realm controls remain. Three additional finite Engine fixtures specify strict and sloppy runs through SpecExec and WasmAot with one compilation worker, a 30-second deadline, Normal(262), and one distinct completion marker. They cover callable Proxy operands, optional Get order, getter-driven move/disposal, all resource value tags, single required Await chronology, setup Throw timing, suppression order, called-Realm errors and Promises, and original getter abrupt/finally order. These are authored controls, not execution evidence.

Current compilation, tests, source guards, runtime, and full conformance are unverified. Verification remains deferred until the complete task source batch is authored, then requires the confirmed aggregate 4096 MiB cgroup ceiling, swap zero, and serial execution. Historical raw slot receipts are preserved separately and do not establish this GC implementation's correctness.
