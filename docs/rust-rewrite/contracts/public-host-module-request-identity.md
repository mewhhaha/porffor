# Public host module request identity

The two retained canonical-order graph controls originally asked for
`{charset:'utf8', type:'text'}` while supplying a Source Text module containing
a named JavaScript export. With Text Module Records supported, those inputs
cannot be positive linking fixtures. `type:'text'` selects an actual text
record, which supplies only its default export, and the supported text selector
is the exact single attribute. Extra charset cannot change a loaded record's
kind or become a filename-based conversion policy.

Both original control IDs retain their independent-host-row and canonical
attribute-order purpose. They use explicit host-defined `charset` and `syntax`
metadata for a Source Text record. This public in-memory host does not claim the
filesystem loader supports those attributes. New paired controls preserve the
original charset/type source inputs as rejections, admit the exact text/default
case using `ModuleSourceIr::text`, reject mismatched record kinds at the same
locator, and reject missing, altered or extra attributes without changing the
retained request key.

No product request matching, module-kind classification, parser behavior or
filesystem policy changes. Normative ownership follows ECMA-262
[ModuleRequestsEqual](https://tc39.es/ecma262/#sec-modulerequestsequal) and the
Text Modules proposal's host-selected
[CreateTextModule](https://tc39.es/proposal-text-modules/#sec-createtextmodule).
The contract is verified by the complete affected IR target after integration;
private formatting and patch checks do not establish a native pass.
