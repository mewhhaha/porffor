# Proxy `[[OwnPropertyKeys]]` handler protocol

## Scope

This contract owns only the handler-acquisition half of Proxy
`[[OwnPropertyKeys]]`: validating a live Proxy, retaining both tagged internal
slots, performing `GetMethod(handler, "ownKeys")`, and either calling that
method or forwarding to the target. The existing list conversion and target
key invariants remain separate consumers after a trap returns.

The four public paths that share this acquisition are:

- `Object.getOwnPropertyNames`;
- `Object.getOwnPropertySymbols`;
- `Object.keys`; and
- `Reflect.ownKeys`.

## Typed local record

Every caller supplies the shared emitter with complete tagged values rather
than positional payload/tag integers:

- `TaggedLocals` for the current traversal object;
- `ProxySlotLocals`, whose private fields are the distinct
  `ProxyTargetLocals` and `ProxyHandlerLocals` roles;
- `TaggedLocals` for the prospective trap; and
- `TaggedLocals` for the trap result.

The target and handler roles cannot be interchanged at a call site. Both tags
are mandatory, and the helper consumes the same `ProxySlotLocals` record as
the single Proxy slot writer and reader.

After that shared acquisition returns, a caller must proceed directly to its
one list/descriptor validator. It may not retain a second inline `"ownKeys"`
lookup, raw Proxy slot reconstruction, Function-only trap call or legacy
runtime-error route. Such a block is unreachable after the typed acquisition's
callable path returns and its nullish path has traversed to a non-Proxy target;
keeping it would restore a second, representation-lossy algorithm owner.

The handler-payload word may be read directly only to classify the current
Object as a Proxy. Once that branch is entered, `emit_load_live_proxy_slots`
is the sole authority that reads `[[ProxyTarget]]` and `[[ProxyHandler]]`. It
must run exactly once per traversal iteration and use
`ProxyRevocationRoute::CurrentFunctionRealm`.

## Observable order

For each Proxy reached by the traversal, emission preserves this order:

1. reject a revoked Proxy in the called builtin's Function Realm;
2. retain the exact tagged target and handler;
3. perform a Proxy-aware `[[Get]]` of `"ownKeys"` on the handler with the exact
   tagged handler as receiver;
4. route an abrupt lookup completion before inspecting the returned value;
5. if the result is nullish, continue with the exact tagged target;
6. if the result is not callable, throw a `TypeError` in the called builtin's
   Function Realm; and
7. otherwise call it through the Proxy-aware Call operation with the exact
   tagged handler as `this` and the exact tagged target as its sole argument.

Retaining the handler tag is observable. Function, Array and arguments
handlers have distinct runtime tags even though they share heap-object
storage. Reconstructing any of them as Object changes strict receiver identity
and can select the wrong `[[Get]]` representation. A Proxy handler must also
retain its complete `[[Get]]` behavior, and a callable Proxy trap must reach
Proxy `[[Call]]` rather than a Function-only call path.

## Completion and Realm boundary

The property read leaves an abrupt completion in its output locals. The
acquisition emitter explicitly returns that completion before `IsCallable`, so
a getter's thrown value cannot be replaced by a generated non-callable error.
The trap call uses the existing throw-propagating Proxy-aware call seam.

The revoked-handler and non-callable-method errors are generated by the
currently executing Object or Reflect builtin. Their prototypes therefore
come from that builtin's Function Realm, including when a created-realm builtin
is borrowed by main-realm source.

## Verification boundary

The durable structure test pins the typed signature, sole slot reader, exact
handler mapping, lookup/completion/callability/call order, current-Function-
Realm errors, the absence of a fabricated Object handler tag, and the absence
of the retired inline `"ownKeys"` acquisition in every caller.

The focused source-free Wasm-AOT fixture covers Function, Array, arguments and
Proxy handlers across all four public consumers. It observes exact getter and
trap receivers, a callable Proxy trap, a thrown lookup sentinel, nullish
fallback to a nested Proxy target, and created-realm revoked and non-callable
errors.

The focused structure test and both source-free CLI fixtures pass on the
current working tree. The remaining centralized checkpoint is:

```sh
./target/debug/lila test262 run built-ins/Proxy/ownKeys --execution-backend wasm-aot --timeout-ms 120000 --threads 4
./target/debug/lila test262 run built-ins/Reflect/ownKeys --execution-backend wasm-aot --timeout-ms 120000 --threads 4
```

Those pinned leaves remain verification obligations, not current-tree pass
claims.

## Non-goals

This seam does not change `CreateListFromArrayLike`, duplicate or property-key
validation, non-configurable/non-extensible target invariants, ordinary or
exotic target key ordering, recursive Proxy descriptor validation, any other
Proxy internal method, Test262 materialization, snapshots, or published
conformance counts. It does not complete T11 or establish full Proxy/Reflect
closure.
