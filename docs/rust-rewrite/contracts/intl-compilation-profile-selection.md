# Selected Intl compilation profiles

`IntlCompilationProfile` admits Minimal and named Custom selections of the
complete pinned finite component domains, and `CustomProjection(CustomIntlProfile)`
selections that construct actual smaller List, RelativeTime and/or DisplayNames images under
one Custom ID. `CustomIntlProfile::new` requires at least one component filter;
each supplied filter is nonempty, structurally checked, sorted and unique.
Selected Locale-backed canonicalization, canonical duplicate checks and each
actual full component inventory check run at image admission. Incomplete
Conformance data cannot enter this compiler
domain. General filtering of all twelve services and full ECMA-402 conformance
remain separate acceptance work.

`IntlDataSelection` belongs to one emission outside its forced-builtin retry
loop. Resolving it constructs one twelve-component bundle with the original
Locale, Number, List, IANA and DateTime foundation owners. The existing provider
constructor admits the complete topology before the bundle can publish frames,
identity or catalogues. Minimal shares a cached complete bundle. Custom keeps
one bundle per emission; profile names do not accumulate in a global cache.
Programs without Intl operations do not resolve the data selection.

A List projection retains only the selected public locales plus `en-US`, while
keeping the actual List rows required by Duration's fifteen associations in the
same owner. Those private profiles cannot be resolved or reminted through public
List wire admission. Duration retains the exact projected List foundation. Actual marker, width and
successful fallback rows are exported from the pinned blob, and the canonical
projected descriptor binds the selected inventory, source pins and foundation
digests. Its ordinary SDK producer and byte admission share the same deterministic
projection recipe.

A RelativeTime projection retains only the requested complete native template
rows plus the actual en-US fallback. It preserves every unit, style, plural
category and Auto literal in those rows. Its canonical native descriptor binds
the selected Locale and complete Number images, source pins, public locale set
and actual numeric associations. Admission recomputes the exact projection from
the pinned full source before publishing the selected template owner. Number
and PluralRules remain complete: they support the selected templates' numeric
formatting without widening public RelativeTime locale support.

A DisplayNames projection retains only the requested exact canonical native rows
plus `en-US`. Each row keeps all six public name domains, all three widths,
language display composition, script and variant associations, and every
date-time field. Unreferenced typed name pools are removed and the retained
associations are densely remapped. Byte admission recomputes that canonical
projection from the pinned CLDR source with the selected Locale authority.
Ordinary locale lookup can still resolve `fr-FR` to a retained `fr` row; a
producer filter must name an actual canonical source row. Excluded aliases
cannot expose unselected public locale rows. Primitive request decoding mints
the selected template owner, and a request from another owner is rejected
before code validation or table lookup.

All three projections can coexist in the same checked twelve-image bundle; a missing filter retains
that component's original complete payload. All other components keep their
complete pinned domains.

The same bundle supplies all twelve component custom sections, the canonical
artifact identity and immutable owned `supportedValuesOf` names. Catalogue
construction validates the selected provider once; the string pool retains
those actual lists rather than borrowing a default global catalogue. Module
assembly cannot select a separate catalogue identity or default image frame.

The library compilation unit retains the chosen profile through worker, emit,
run and cache paths. Cache framing includes the closed profile discriminator
and the exact validated Custom ID. Cache version eight binds discriminator two
to one ID followed by independent presence tags for List, RelativeTime and DisplayNames;
each present filter has a count and length-prefixed sorted structural locales.
Moving a filter between components, omitting it or changing one locale therefore
cannot reuse another selection's artifact. Input order produces the same key.
The CLI exposes `--intl-profile custom:ID --intl-list-locales es,he
--intl-relative-time-locales fr,pl --intl-displaynames-locales fr,ja`.
Any nonempty subset of the three locale flags may be supplied,
in any order, under the one Custom ID. Duplicate flags, empty or structurally duplicate locale
lists, invalid identities and ignored backend selections reject before source
loading. Minimal cannot carry these projections. Non-Wasm consumers report a
generic unsupported custom Intl projection instead of treating it as List-only.

The SDK, emitter and product consumers form one source batch. Source review
and formatting establish no compilation, runtime or conformance result. Exact
Custom artifact, catalogue, operation and CLI controls must run at the combined
verification checkpoint. The DisplayNames successor adds actual DisplayNames-only
and three-component emitted frames, physical payload shrinkage, exact selected
rows, unchanged unfiltered frames, native wire owner reminting, six domains and
three widths, required fallback and aliases, cache field independence and
CLI/SDK artifact equality for both flag orders. Strict and sloppy scripts and
modules use the ordinary compiler and artifact runner. These controls remain
authored and unrun.
