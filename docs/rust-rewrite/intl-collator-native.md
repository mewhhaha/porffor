# Pinned native Collator data lane

The native service consumes the genuine ICU export for `icu4x/2025-05-01/77.x`, commit `594c9b890abfa794a259162f1a29513445365f89`, through the locked ICU4X 2.0 kernel. Its nine marker implementations include genuine `search` and `searchjl` data, implicit Han weights, and the small NFD data and tables. It uses its explicit generated provider for every constructor; stock compiled sort data is never substituted when a search profile is absent.

Root actually compiled and ran the isolated export and admission foundation. The export receipt is `49e95a825c6a74992eca004da76f312ddb0f1ae71ffd088062f204923a4d540e`; the admission receipt is `3fe60ad649669c2e0a99e4374e3871bfaef222e339ebb3b6f1c808dd710f46e6`. Admission covered 144 source metadata identities and 7,056 real constructors, including German sort/search, Thai defaults, all four sensitivity mappings, caseFirst/numeric overrides, canonical Hangul, raw UTF16 and finite comparator controls. These are foundation results. They do not establish product conformance or a service AvailableLocales count.

The service starts with the pinned CLDR canonical locale inventory carried by the existing number-data archive. This is only a locale-name source; no NumberFormat constructor, JS numeric coercion or formatting operation is used to create a Collator. Each candidate must independently load complete default-sort and genuine-search marker associations before it enters AvailableLocales. A missing search profile rejects setup. For named sort collations, a missing metadata identifier excludes that association; once metadata exists, any failure in the complete real constructor rejects setup. All effective marker locales come from the responses actually consumed by that constructor.

Data-purpose classification uses the pinned `CollationType` domain. `Standard` is the default/reserved purpose; `Search` and `Searchjl` are documented special search purposes and remain private. All other known types are candidates for sort data, including `Phonetic`. A future unknown ICU enum case rejects setup. A public co value enters a locale's list only after its real sort profile loads. The public AvailableCollations union is sorted and deduplicated from those admitted associations. Keeping searchjl private is this service's chosen data-purpose policy, not a claim that ECMA-402 universally forbids that name.

`ResolvedCollatorLocale` retains one canonical published locale and an immutable profile owner, selected Usage, numeric and caseFirst. The profile carries actual default ignorePunctuation; search's owned default sensitivity policy is variant, as is the prescribed sort default. Locale resolution uses the existing complete-value CLDR alias authority, including lossless compound `true` subtags, and keeps only supported co/kf/kn additions. SupportedLocales uses the same actual set. The final checked configuration adds the two options observed later in Wasm; a compare request cannot replace its retained profile with unrelated raw indices.

The primitive host ABI advances to 9, with consumed operations 24 ResolveCollatorLocale, 25 SupportedCollatorLocales and 26 CompareCollator. Every message has the two-u64 version-1 header, followed by the approved conditional counted-field layout. Native decoding checks the closed option domains, complete extents and absence of trailing bytes. Compare receives two ordered lossless UTF16 arrays and returns only Equal, Less or Greater; Wasm owns all user-visible coercions, ordering, object publication and cached bound functions.

Comparison calls the pinned `compare_utf16` directly. Valid pairs are scalar values; isolated units receive ICU replacement weights, and different malformed inputs may compare equal. The root policy inference is supported by captured Unicode 16 UCA section 10.1.1 and the frozen ECMA-402 comparator constraints. There is no lexical tie-breaker. The archived actual foundation controls establish meaningful finite regressions rather than a proof for all strings.

The immutable catalogue is cached in one OnceLock; its complete candidate/profile admission cost is paid at first native setup. Each completed compare constructs the actual kernel options from its retained profile and checks the stable consumed marker association. No speculative cache or alternate selector is added. Product startup cost and complete service counts remain measurements for the coherent batch run.

`scripts/generate-intl-collator-data.py --check` verifies full primary crate archives against real locks, the genuine ZIP checksum/CRC, exact generated files, archived actual receipts and source identity. `--reexport --check` additionally executes the isolated pinned Cargo exporter under target and compares all ten generated outputs byte-for-byte; this expensive recipe is reserved for the batch executor. The generator never patches product data during reexport. Its exported-file order reproducibility remains a real check, not an inferred claim from the first successful export.

The root must regenerate Cargo.lock after composition to add the direct existing `icu_normalizer = 2.0.1` and `icu_collections = 2.0.0` dependency edges and the provider baked feature closure. No package checksum or lock was guessed by this source lane. The current supportedValuesOf bridge receives the actual collation union through a separately sealed one-file attachment; that bridge and its earlier absent-Collator receipt remain historical inputs. Compilation, eight native service tests, two real host capacity/overlap tests and complete Engine/pinned verification remain mandatory after whole-batch composition.
